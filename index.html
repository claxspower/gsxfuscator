Quick start

Save this one-line example as example.lua to try your first build.

  1. Open Obfuscator and select or drop your file. The panel accepts .lua, .luau, and .txt files containing Lua source code. Drag and drop works for all three extensions.
  2. Press Run to compile the file. The downloaded example prints 42 when you run it in Lua.
  3. Save the generated Lua file with Download. Keep your own backups: GsXFuscator does not store build history.

Reading, Graphite Light & Night

The dashboard uses one graphite-gray palette; theme colors and font menus are removed. Go to Settings → Appearance to choose Light or Night, or enable Large reading text. These settings persist in this browser when storage is allowed.

Elegant is retained for display headings. Instructions, buttons and longer passages use clear system UI fonts, with generous spacing, visible keyboard focus and no dependency on downloading a webfont. Browser text zoom and accessibility settings are supported.

Animations are subtle. If your device requests reduced motion/data or reports low memory, decorative motion and effects are reduced automatically; all essential operations remain available. Reduced-motion is also honored through operating-system settings.

Performance and memory

VM size and opcode variety can increase load time and memory. A large obfuscated file is not evidence of stronger security. Avoid compiling the same source repeatedly on low-memory devices; export and keep the file you need.

  1. Record source size, output size, Lua version and preset.
  2. Measure a cold start and several warm executions of the same output.
  3. Compare median wall time and peak resident memory against the original.
  4. Check program output for equivalence and repeat on your target device.

V0.5 loader maintenance replaces per-bit LZSS reads with a bounded word reader and combines FNV/Adler checks into one byte pass. In one Lua 5.4 cold-start fixture, Strong Sealed Auto improved from a 0.573-second median to 0.431 seconds across four runs. This is a local sample, not a universal speedup or a low-RAM device guarantee.

For reproducible measurements use python v2/tests/benchmark_matrix.py --lua lua5.4 --runs 5 in the source package. The CLI exposes --vm-size compact for size-constrained deployments, but it reduces decoy diversity; the web policy uses Strong/compact VM.

Security model & limitations

GsXFuscator is an obfuscator, not an encryption vault. A determined analyst can decode the outer transport and inspect the resulting VM; this is not necessarily the original source. Runtime debugging, hooking and memory snapshots are possible when an attacker controls the Lua interpreter.

Anti-tamper and anti-debug checks detect selected changes to references, behavior and VM structures, but they do not guarantee that all modifications or debuggers will be detected. FNV and Adler checksums detect corruption; they are not keyed authentication or signatures.

Do not embed reusable secrets or authorization decisions solely in the client-side output. See v2/SECURITY.md for boundaries and the validation checklist.

    Rules & Guidelines

    These guidelines apply to building and sharing Lua files with GsXFuscator.

    1

    Legal Use Only

    Use scripts you own or have permission to modify.

    2

    No Malicious Scripts

    Malware, phishing and scripts intended to harm other people or systems are prohibited.

    3

    Roblox ToS

    Follow the Roblox Terms of Use when distributing or running scripts on Roblox.

    4

    No Guarantees

    Code distributed to a client can be inspected. Keep credentials and confidential business logic on your server.

    5

    Build privacy

    GsXFuscator does not save build history or upload generated files. Only appearance and profile preferences are saved locally when storage is available.

    6

    Access restrictions

    Harmful use can result in loss of access.

    7

    Keep Secrets Server-Side

    Never embed API keys, passwords or sensitive tokens in client-side Lua. Obfuscation cannot keep secrets from someone controlling the runtime.

    8

    Test Before Distribution

    Run the protected script in the intended Lua environment. Compare behavior, startup time and memory use with the original before releasing it.

    GsXFuscator is provided as-is. You are responsible for the scripts you distribute.
